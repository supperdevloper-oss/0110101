## 1) شنو كان واقع بالضبط؟

شفت الداتا ديالكم (`crm_data.json` + `audit.log` + `journal.log`) ولقيت الدليل:

- 59 تعديل دارتهم **Meryam من الهاتف** نهار 09/11 بين 15:40 و 15:47 مسجّلين فـ `Historique`
  (`T → Tt → Ttt → Tttt`)، ولكن **السطر فالسيرفر باقي فارغ** (`remarques: ""`, `statut: ""`
  و `_u` مازال هو وقت الإنشاء 14:41).
- يعني التعديل كيبان فالشاشة، ومن بعد ~15 ثانية كيرجع فارغ: هو بالضبط وقت الـ **poll**
  (`setInterval` كل 15000ms) لي كيجيب نسخة السيرفر القديمة ويكتبها فوق `localStorage`.
- التعديلات الصغار (`Historique`, `worktimes`) كانو كيوصلو للسيرفر عاديين.
  الكبير `paraveda_orders_v5` بوحدو **2.5 ميغا** (≈ 5MB بـ UTF-16 = الحد الأقصى
  ديال `localStorage` فالهاتف). ملي كيمتلئ الكاش، `setItem` كيخسر بصمت، والـ POST
  كيصيفط 2.5MB على شبكة الهاتف → كيخسر هو الآخر → والـ poll كيمسح التغيير.
- زيد عليها: `api.php` كان كياخد **ساعة الهاتف** (`t = Date.now()`) كمرجع. هاتف
  ساعتو متأخرة → `t < prevT` → السيرفر كيرفض التعديل / `crm_merge_list` كيخبيه.
- و `paraveda_reset_v1` (طابع مسح قديم ديال شتنبر) كان كيمسح كاش كل هاتف جديد
  و كيدير `location.reload()` فنص الخدمة.
- و `.htaccess` كان كيخزّن `*.js` بـ `immutable` **عام كامل**: الهاتف كان كيحتافظ
  بـ `sw.js` / `push.js` / كود قديم حتى بعد ما كترفع نسخة جديدة.

## 3) «لعيبة الكاش» لي طلبتيها 🧹

كاينة دابا فـ **`pv-cache-guard.js`**: كل **5 ثوان** كتمسح الكاش **التقني**:

- `CacheStorage` ديال Service Workers القدام،
- تحديث الـ Service Worker،
- طلب طري للسيرفر بـ `?_=...` (باش حتى الـ proxy/ISP ما يرجّعش نسخة قديمة)،
- و `index.html` كيتحقّق من الداتا كل 5 ثوان (ETag → 304 بلا تحميل).

وفالجنب كاين شريط صغير (`✅ محفوظ` / `⏳ كيتسجل…` / `⚠️ الشبكة مقطوعة`)،
وضغطة عليه كتدير `🧹 مسح الكاش` يدوي + تجيب أحدث داتا.

> ⚠️ **ما مسحناش `localStorage` ديال الطلبيات كل بضع ثوان** — هاديك هي الداتا براسها،
> لو مسحناها كنعاودو نخسّروا كلشي. كنمسحو غير كاش المتصفح/الشبكة. تقدر تبدّل المدة:
> `window.PV_CACHE_MS = 3000;` (و `window.PV_SYNC_MS` باش تبدّل وتيرة التزامن).

## 4) كيفاش ترفعوها للسيرفر (مهم)

ارفعو **هادي 6 ملفات** فـ `public_html/` (racine الموقع)، فوق القدام:

```
index.html
api.php
.htaccess          (أو htaccess.txt → سمّيه .htaccess)
sw.js
push.js
pv-cache-guard.js  ← جديد
```

- ❌ **ما ترفعوش** `legacy/`, `tests/`, `tools/`, `paravidaaaa.zip`, ولا `crm_data.json`
  ديال هاد المشروع. `crm_data.json` لي **فالسيرفر** هو الداتا الحقيقية ديالكم → خلّيوه
  كما هو، الإصلاح ما كيبدّلوش.
- ✅ النسخة القديمة ديال `api.php` (v3.94) والجديدة (v3.105) متوافقين، ولكن خاص
  **الجوج يترفعو مع بعض**: `index.html + api.php`.
- بعد الرفع، **مرة واحدة فكل هاتف**: سدّو الـ CRM، دوزو **Ctrl+F5** (أو ضغطو على
  الشريط `🧹` من داخل التطبيق). هادي باش الـ Service Worker القديم يتبدّل.
- للتأكد: `api.php?export=version&token=...` خاصو يرجّع `"apiVersion":"3.105"`،
  والشريط الصغير فأسفل الصفحة كيوري `✅ محفوظ`.

## 6) للمطوّر: شنو كيوقع فكل تعديل دابا

1. البنت كتكتب فالخانة → React كيحدّث `localStorage` (مضغوط، فالذاكرة فالحين).
2. `aa(key)` كيعلم المفتاح «معلّق» و كيحسب **الدلتا** (بصمة لكل صف).
3. بعد 400ms → POST صغير `{key, t, ct, d:[صف], delta:1}` + نسخة فالـ outbox.
4. `api.php` كيصحّح الوقت، كيدمج الصف تحت القفل، كيخزّن، كيرجّع `t` ديال السيرفر.
5. أي `poll` كيجي فهاد الأثناء **كيتجاوز** هاد المفتاح (درع) → حتى حاجة ما كتمسح.
6. نجاح → الـ outbox كيتنظّف، والسنابشوت الجاي كيوحّد النسخة النهائية للجميع.
7. `pv-cache-guard.js` كل 5 ثوان كيمسح الكاش التقني ويطلب داتا طرية بلا ما يلمس الداتا.
